Shopify CEO Tobi Lütke，2026年初个人代码提交量暴涨了10倍。要知道他公司里有4000研发、市值1500亿美金，居然天天在 Github 上提PR...

为什么？

因为编程范式转移了。写代码这件事不再消耗体力，真正稀缺的东西变成了判断力。

## **此间乐，不足为外人道也**

AI Coding这东西，就是让AI Agent自主跑完整个编程任务的那种模式，不是 Copilot 帮你补全几个字母那种小意思，是真的超级上瘾。

Garry Tan（陈嘉兴）写代码写到凌晨5点，不是在拼命，是停不下来。所有认真试过的老程序员，说的都是同一种感觉：晚上9点冒出一个念头，凌晨2点已经是一个能跑的产品。不是原型，不是线框图，是真正能部署正式服的业务代码。

这种爽感，编程这行从来没给过我们。

笔者写了十几年代码，说句掏心窝的话。传统编程的时间分配大概是五成在搞配置、弄编译、处理工具链冲突、剃各种牦牛毛；四成是开会、对需求、打嘴炮；一成才是真正有趣的创造性决策。

AI agent coding把这个比例翻过来了。八成时间花在真正有意思的事上，人类来定架构怎么选、产品怎么取舍、交互怎么做，然后脏活累活全丢给agent。

你终于在做你一直希望编程应该是的那份工作：**纯粹的创造性思考**，想到即所得。

这是信号枪响了。当工作本身变得让人欲罢不能的时候，能做这件事的人会比任何被工单驱动的人投入更多、走得更远。

那些把**&nbsp;AI 代码率搞成 KPI 考核**的公司（是的我在点名你，字节阿里小米），正在把自己的工作环境变得更加形式主义、更加无聊。最好的工程师会用脚投票。这件事古往今来没变过。

## **大厂 AI Coding 提效，卡在10%～30%**

这部分可能让人不舒服，但笔者觉得有必要讲清楚。

先说技术本质。**Claude Code本质就是深度优先搜索（DFS）加全文检索（grep）**。生成代码、bash跑测试，不对就退回来换一条路。

在小代码库里这招非常好使。模块边界清晰，文件命名规范，文档和代码挨在一起，搜索空间可控。

但你把这个agent扔进一个一千万行的大厂monorepo里，搜索直接炸掉。Agent搜一个函数名，400个结果散落在12个服务里。

不是agent蠢，是**代码太陈年屎山、水太深了**。真正的关键上下文甚至于不在代码里！在钉钉和飞书聊天记录里，在复盘文档里，在当初搭这个系统那三个人的脑子里。

Claude两手一摊：实在搜不到这些口耳相传的上下文，臣妾做不到啊！

![图片](https://mmbiz.qpic.cn/sz_mmbiz_png/MUNZNTOIlMiaiaickNRdN1p3X8npDQcMQbMwicaaFp2lUfuicT5FetV14r5QPs6b77EnpuNiaABA3uiazzVPicWphMeRnzjadPVOSmsUF7l98hOmBrk/640?wx_fmt=png&amp;from=appmsg)

这不是模型更强就能解决的事。这是在一张太大、太乱、连接关系太隐晦的图上做搜索的根本困境。你给agent无限算力无限智商，它依然不知道这个接口暗暗依赖另一个团队的定时任务，那个任务凌晨三点跑一次。

屎山这种东西压根不是为任何智能体高效理解而设计的。人类新员工也一样抓瞎。

## **最精英的程序员，非常不适合继续待在大厂**

更要命的是，整个组织都不是为 AI Coding 设计的。人巨多，流程巨长，既得利益盘根错节。你想用 Agent 提效十倍，旁边有八个人的工作量要因此被质疑，你觉得推得动吗。

大厂大概率不会给你最好的模型。笔者亲身体感，Opus 4.6 和其他模型之间是代差级别的鸿沟，Gemini 3.1 Pro 和 GPT 5.4 都时不时冒出匪夷所思的 bug。**但很多大厂还在用自研模型搞合规搞保密**，等于单手绑在身后作战... 有些公司连 Cursor 二十美金一个月的会员费都要几个人共享。何其荒谬。

**大厂也不会给你十倍薪资。**论资排辈，薪酬带宽，公平性原则，S-Player 在大厂的薪酬体系里根本体现不出五十倍效率的价值。

## **文艺复兴工程师：一个人就是一支队伍**

现在讲让人振奋的部分。

Startup 创始人们说自己有20到50倍生产力提升，不是说写代码快了20倍。如果只是写代码快了20倍，考虑到写代码本身在交付链条里占比就不大，整体大概也就快3倍。

真正的倍增来自另一个地方：一个人同时hold住产品方向、工程架构、测试策略、部署管线和生产监控，用AI agent在所有这些领域执行，**不需要切上下文，不需要等别人**。

![图片](https://mmbiz.qpic.cn/mmbiz_png/MUNZNTOIlMgKXmm0Q0uy2q5ibbxfmk5jPACkIcxny6uSicMnYwYRC0jTpKiaZ3QOB6T12WOapNh4wT16yoiaGic49D9OUicjicpfeBy6micibda6nF18/640?wx_fmt=png&amp;from=appmsg)

笔者管这种人叫文艺复兴工程师。不是一个写代码更快的专才，而是一个把五个专才之间的协调成本彻底消灭掉的通才。

**Brooks法则：往延期的项目里加人只会更延期。**

因为沟通开销随人数呈平方增长。5个人有10条沟通线，10个人有45条。

文艺复兴工程师加AI agent有多少条？零。一颗脑袋，一个意志。没有我以为你说的是另一个API这种事。没有等三天让基础设施的同事review你的改动。没有写工单跟另一个组解释你到底想要什么。

省下来的时间不在代码生成上。在于彻底消灭了那些飞书/钉钉来回、对齐会、缺乏上下文的文档评审、部署排队，以及一切跨组依赖。

周一早上，读用户反馈，定一个功能方向，这是产品。勾画数据模型和API，这是架构。让agent去实现，这是工程。让另一个agent写集成测试，这是QA。Review合并，自动部署，这是运维。盯一小时错误率，这是监控。

周一下午，功能上线。没有站会，没有sprint planning，没有跨组依赖工单。

这不是幻想。这就是AI-native创业公司的人此刻每天在干的事。

## **但这事只有一种人干得了**

25岁的应届生做不了文艺复兴工程师。

不是因为不聪明，不是因为学不会agent coding。而是因为他**没有产品直觉，没有架构品味，没有被生产事故教训**出来的那种本能。

30～45岁的人呢，当过tech lead，值过夜班on-call，和产品经理拍过桌子，凌晨三点debug过线上事故，带过团队，亲手发布过失败的东西。这个人能把整个闭环装在脑子里。AI负责执行，人负责提供那种融会贯通的判断。

你在职业生涯里踩过的每一个坑，现在都是agent可以跳过的岔路。你跟agent说，别试这个方案，这条路走不通，原因如何如何，直接从那个方案切入。你攒了十几年的经验，每一条都是一次高效剪枝。经验等于剪枝质量，剪枝质量等于速度。

十年弯路，一朝成金。这话搁以前是鸡汤，现在是结构性成真了！

## **极端的两极分化**

说一点不太舒服的话。

AI 不会替代程序员。但 AI 会造成程序员群体内部极端的两极分化。

一头是驾驭 Agent 的人，一个人顶一个团队，价值暴涨。另一头是只会写 CRUD 的人，被 Agent 直接替代。

中间地带，几乎没有。

这话不中听。但笔者觉得，对真正在乎自己前途的人来说，早知道比晚知道好。

## **创业公司才是 AI Coding 的主场**

一个今天从零搭建的创业代码库，可以专门为AI agent的工作方式量身定做：**小仓库**，清晰边界，spec和代码放在同一个目录，一切都能被检索到，没有暗依赖。

这不是所谓更好的工程实践。这是在为深度优先搜索专门铺一条它跑得通的路。

**文档和代码在同一个仓库里，永远是最新的。**

![图片](https://mmbiz.qpic.cn/mmbiz_png/MUNZNTOIlMia4LHGkUqfoVO5AT3paMjDh66hX2biczo2BjUxysiclCkzM1J24Mylo3AlYxHrldCNsabrLeSWJptnesgPluCugGqM0fibrkIAEnc/640?wx_fmt=png&amp;from=appmsg)

Agent读spec，写代码，顺手更新文档，一个循环走完。文档是活的。这就从根上解决了大厂里搜索失效的问题。

Agent不需要口耳相传的部落知识，因为所有东西都写在代码旁边，还有别的agent帮你时时更新。

今天Opus 4.6发布，明天全员用上最好的前沿模型。新模型出来了如果好，不管多贵，直接切。

代码到上线，分钟级。没有评审委员会，没有staging排队。CI跑过，直接部署。AI在生成端省下来的时间，一秒不漏地转化成交付速度，因为中间没有任何官僚机构把省下来的时间悄悄吃掉。

## **几点心得**

最近写了1000个 PR，踩了一些坑，有些感悟渐渐沉淀下来：

**文件系统即架构**&nbsp; 这一条笔者感触最深。先写 spec，用 markdown 把需求和设计交代清楚，让 Agent 读 spec 再写代码。不是先写代码再补文档，那条路在 Agent 时代彻底走不通了。每个模块要能被命令行调用、被 API 调用，因为 Agent 是通过 CLI 和 API 与你的系统交互。仓库要拆小，职责清晰，边界分明。

**像 Agent 一样思考**&nbsp; 这是需要刻意转变的心智模型。你不是在用 AI 辅助自己写代码，你是在指挥一支 Agent 大军。每个 Agent 需要明确的目标、充分的上下文、清晰的边界、可验证的产出。这和管理一支工程团队并无本质区别，只不过反馈周期从以天和周计变成了以秒计。做过 Tech Lead 的人天然有优势。

**Skills 系统是能力的最小复用单元**&nbsp; Garry Tan 开源的 gstack 本质上就是一套 Skills 系统，十五个预设角色涵盖 CEO、设计师、工程经理等。Skills 就是可复用的指令包，让 Agent 在特定场景下表现得像领域专家。写一次，团队所有人加所有 Agent 都能用。

**简洁、可观测、可扩展**&nbsp; 三万行能做的事用两千行做。不是偷工减料，是把逻辑从代码搬到了 prompt、config、rule 里面。每个 Agent 操作必须有 trace，每个决策可回溯，黑盒等于失控，铁律。架构设计要面向 Agent 的扩展性，Hook、Tool、Plugin，反馈闭环越短越好。

**本质是寻路，不是生成**&nbsp; AI Coding 最准确的比喻不是代码生成器，而是在一片巨大的方案空间里寻路。Agent 负责搜索，你负责指引方向。老手比新手快十倍不是因为打字快，是因为知道哪些路不必走。天下武功唯快不破，快在判断，不快在手速。

**和代码补全是完全不同的物种**&nbsp; Agent Coding 是让你的思考产出比提升几十倍，Agent 做执行，你做判断。绝不能还停留在 Cursor 里、OpenClaw 也不适合研发，Metabot 是当前比较好用的 Coding Agent

## **35 岁再也不是问题**

讲一个朋友的事。

名校出身，第一份工作 Google，后来在某大厂做到技术总监。管几十号人，天天开会，代码离手很多年了。

最近他开始自己 AI coding，产出至少相当于二十个人。管理的活儿大幅缩减。上次见面，满眼放光。那种光笔者太熟悉了，是技术人重新触碰到代码时才有的光。

这件事让笔者感慨良久。

这些年来，有多少真正热爱编程的人，其实并不擅长也并不享受处理人际关系。做管理是不得不为之。技术路线到了天花板，往上只剩管理一条道。于是一个个优秀的工程师变成了疲惫的管理者，心里那团火慢慢就灭了。

现在不同了。一个打二十个，一个打五十个。不需要管二十个人才能有二十人的产出。纯粹靠自己的技术判断力和 Agent 编排能力，就能撑起一片天。

回到纯粹的技术快感。此乐何极。

即便还做管理，穿透力也今非昔比。能自己写代码的技术管理者，与只会听汇报开会的技术管理者，穿透力判若云泥。你能直接验证架构方案，直接读代码发现深层问题，直接修复关键 bug。不用等层层汇报，自己便能看穿全局。陈嘉兴 和 Tobi Lütke 如今正是这个模式。

经验等于剪枝质量。你积累的每一年，现在都是实打实的杠杆。年龄不再是劣势，年龄是你最深厚的资本。

所谓 35 岁危机，在 Agent 时代，不攻自破。

有经验的中登（中年攀登者）们，你们的黄金时代刚刚开始。
